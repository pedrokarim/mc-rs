Roadmap

Development phases and planned features for MC-RS.

MC-RS is being developed in incremental phases. Each phase builds on the previous one, adding new systems and capabilities. The project follows a "plan par plan" approach — completing each phase fully before moving to the next.

Phase 1: Foundation

DONE — This phase is complete.

The foundational layer that gets a player connected, authenticated, and into a world.

  • RakNet UDP transport — Full RakNet implementation with reliability, ordering, fragmentation, and MTU discovery
  • Bedrock protocol codec — Packet encoding/decoding for protocol version 975 (Bedrock 1.26.20)
  • Login sequence — Complete login flow: NetworkSettings, Login, JWT verification, PlayStatus, ResourcePacks, StartGame
  • AES-256-CTR encryption — ECDH P-384 key exchange and encrypted packet transport
  • Flat world generation — Superflat chunk generation with grass, dirt, and bedrock layers
  • Player movement — PlayerAuthInput handling with server-side position tracking
  • Chat system — Bidirectional chat with Text packets

Phase 2: Player Basics

DONE — This phase is complete.

Multi-player support, server management, and world variety.

  • Multi-player sync — AddPlayer/RemovePlayer, position broadcasting, player list
  • 65 built-in commands — full vanilla command set with tab-complete and entity selectors
  • Terrain generation — Simplex 3D terrain generator with biomes, ores, trees and water
  • Time and weather — Day/night cycle with SetTime, weather system with clear/rain/thunder
  • Player persistence — Save and restore player position, game mode, and state across sessions
  • Configuration — server.toml with server, world, and gameplay sections
  • Dynamic spawn — Spawn position adapts to terrain height

Phase 3: World Interaction

DONE — This phase is complete.

The phase that makes the world interactive — players can modify terrain and manage items.

  • Block breaking and placing — InventoryTransaction handling for block interactions
  • Item system — Item definitions, stack management, durability
  • Inventory management — Full inventory with hotbar, armor slots, crafting grid
  • Chunk persistence — Save modified chunks to LevelDB for world persistence across restarts
  • Block updates — Neighbor updates, gravity blocks (sand/gravel), fluid flow
  • Creative inventory — Full creative mode item catalog

Phase 4: Entities & Combat

DONE — This phase is complete.

Bringing the world to life with mobs, combat mechanics, and survival systems.

  • Entity system — ECS-based entity management with AddActor/RemoveActor
  • Mob spawning — Natural mob spawning based on light level and biome
  • Basic AI — Pathfinding, hostile mob targeting, passive mob wandering
  • Combat system — Melee and ranged attacks, armor reduction, knockback
  • Hunger and health — Survival mechanics with hunger bar, natural regeneration, starvation
  • Potion effects — MobEffect packets for speed, strength, poison, regeneration, etc.
  • Experience and levels — XP orbs, level progression, enchanting cost

Phase 5: Game Systems

DONE — This phase is complete.

Advanced gameplay systems that complete the survival experience.

  • Crafting — Crafting table recipes, shaped and shapeless, smelting
  • Enchanting — Enchanting table, anvil combining, grindstone disenchanting
  • Advanced world generation — Biomes, caves, ores, structures, trees
  • Redstone basics — Redstone wire, repeaters, torches, pistons
  • Container blocks — Chests, furnaces, hoppers, dispensers
  • Farming — Crop growth, animal breeding, bone meal

Phase 6: Plugin System

DONE — Lua runtime implemented.

Extensibility through a Lua plugin runtime.

  • Plugin manifests — PMMP-style plugin.yml discovery (name, version, commands, permissions)
  • Lua plugins — Lua 5.4 scripting via mlua
  • Event system — Subscribe to server events (e.g. PlayerJoin) from Lua
  • Scheduler — Schedule Lua callbacks after N server ticks
  • Custom commands — Commands declared in the manifest with a Lua handler
  • Forms UI — Server-driven forms with 8 custom layouts via the title-flag dispatcher
Not planned (today): a sandboxed WASM runtime. The current extension story is Lua plus the native Rust command/runtime traits.

Phase 7: Server Tooling

DONE — This phase is complete.

Operational tooling and administration.

  • Anti-cheat — Movement validation (NaN reject, void kill), reach/speed checks
  • RCON protocol — Remote console for server administration
  • Query protocol — GameSpy4 query for server-list pings
  • Web admin panel — Live metrics, console, players, users, world, audit log
  • Scoreboard & boss bars — Objectives, display slots, boss bars
  • Permissions — Operator levels, whitelist, ban list (name + IP)
  • Advanced commands — /setblock, /fill, /clone, /scoreboard, /effect, /enchant, /summon, …
  • Resource packs — Server-driven pack delivery + custom UI pipeline

Phase 8: Vanilla Parity & Polish

IN PROGRESS — Ongoing work.

Closing the gap to full vanilla parity and tuning performance.

  • Complete coverage of every block behaviour, structure and redstone device
  • Full mob roster with parity AI and drops
  • Performance tuning (chunk caching, packet batching, entity culling)
  • Postgres / MongoDB backends for the web panel
