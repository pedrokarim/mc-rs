Plugins

Extend the server with Lua 5.4 plugins — manifests, events, a tick scheduler, and custom commands.

MC-RS ships a plugin runtime built on mlua (Lua 5.4). Plugins are discovered from a plugin.yml manifest in the PocketMine-MP style, then loaded, enabled, and ticked alongside the server.

Today: the extension story is Lua plus the native Rust command/runtime traits. A sandboxed WASM runtime is not implemented.

Plugin layout

plugins/
└── MyPlugin/
    ├── plugin.yml      # manifest (name, version, commands, permissions)
    └── main.lua        # entry point referenced by `main:`

Manifest (plugin.yml)

name: ExampleLua
version: 1.0.0
main: main.lua
api: ["1.0.0"]
author: you
load: POSTWORLD          # or STARTUP
commands:
  hello:
    description: Say hello
    usage: /hello
    permission: example.hello
permissions:
  example.hello:
    default: true

Capabilities

APIDescription
CommandsRegister a Lua handler for each command declared in the manifest.
EventsSubscribe to server events (e.g. PlayerJoin) with a Lua callback.
SchedulerSchedule a callback to fire after N server ticks.
Log / BroadcastWrite to the server log or broadcast a message to all players.

Example (main.lua)

-- runs when the plugin is enabled
mcrs.log("ExampleLua enabled")

-- command handler declared in plugin.yml
mcrs.command("hello", function(sender, args)
    mcrs.broadcast("Hello from Lua!")
end)

-- react to an event
mcrs.on("PlayerJoin", function(player)
    mcrs.log(player.name .. " joined")
end)

-- run something 100 ticks (5s) from now
mcrs.after(100, function()
    mcrs.broadcast("5 seconds later...")
end)
Note: the exact Lua host API surface is evolving. Use /plugins in-game to list loaded plugins and /reload to reload them.

Native command engine

Under the hood, plugin and built-in commands share the same generic engine in mc-rs-command and drive the world through the ServerCommandRuntime trait. See Commands for details.
