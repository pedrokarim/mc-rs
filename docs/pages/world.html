World System

Chunk-based world with flat and Simplex 3D terrain generation, biomes, and LevelDB persistence.

Chunk Format

The world is divided into vertical chunk columns, each spanning 16 blocks in X and 16 blocks in Z. The Y range extends from -64 to 319 (384 blocks total), divided into 24 sub-chunks of 16×16×16 blocks each.

Each sub-chunk uses paletted storage with a dynamic number of bits per block. The palette maps local indices to block network IDs. Sub-chunks that contain only air are omitted during network serialization.

// Sub-chunk paletted storage
SubChunk {
    version: u8,              // sub-chunk version (8)
    storage_count: u8,        // number of block storage layers (1 or 2)
    storage: [PalettedStorage], // block layers (layer 0 = blocks, layer 1 = waterlogged)
}

PalettedStorage {
    header: u8,               // (bits_per_block << 1) | 1  (runtime flag in bit 0)
    block_indices: [u8],      // bit-packed palette indices for 4096 blocks
    palette_count: VarInt32,   // number of entries in the palette
    palette: [VarInt32],       // block network IDs (runtime hashes)
}

// Special case: single-block sub-chunk (bits_per_block = 0)
// Header byte: 0x01 (0 << 1 | 1)
// NO palette count written, just the single block network ID
Network flag: The header byte has bit 0 set to 1 for network (runtime) serialization. This distinguishes it from disk (persistence) format where bit 0 is 0. MC-RS only uses the network format since chunks are not persisted to disk.

Biome Sections

Each sub-chunk includes a biome section serialized after the block storage layers. Biomes use the same paletted encoding as blocks but at 4×4×4 resolution (64 cells per section instead of 4096).

For chunks with a single biome (the common case in MC-RS), the biome section is encoded compactly: a header byte of 0x01 (0 bits per entry, runtime flag set) followed by a single VarInt32 biome network ID. No palette count is written for single-biome sections.

Terrain Generators

MC-RS includes two terrain generators, selectable via configuration.

Flat Generator

The flat generator produces a simple layered world:

  • Y = -64 — Bedrock layer
  • Y = -63 to -59 — 5 layers of dirt
  • Y = -58 — Grass block on top

Block IDs are resolved as sequential indices from canonical_block_states.nbt. All sub-chunks above the surface layer are empty (air) and omitted from the network payload.

Normal Generator (Simplex 3D)

The normal generator uses Simplex 3D noise to carve terrain, combined with a temperature/rainfall biome classifier. Each column's surface, sub-surface and decoration are chosen by its biome.

The generator produces:

  • 11 biomes — classified from temperature & rainfall noise
  • Stone / dirt / grass / sand / gravel / snow — biome-aware surface and sub-surface layers
  • Water — fills columns below sea level
  • Ores — vein placement by depth (coal, iron, gold, redstone, diamond, …)
  • Trees — species per biome
  • Structures — villages, temples, mineshafts, strongholds, ocean monuments and more

Other dimensions (Nether, End) and their generators/structures are also implemented.

Parallel generation: Chunk generation is offloaded to tokio's blocking thread pool via spawn_blocking. Multiple chunks can be generated in parallel, and the results are cached for subsequent player connections.

Block Network IDs

MC-RS sets block_network_ids_are_hashes=false in the StartGame packet. Block runtime IDs are therefore sequential indices into canonical_block_states.nbt — the block at index 0 has network ID 0, index 1 has ID 1, and so on.

The file is parsed at startup using Network Little-Endian NBT decoding (ZigZag VarInt for integer types), and each block state's position in the file becomes its network ID.

// canonical_block_states.nbt format
// Network Little-Endian NBT (ZigZag VarInt for int types)
// Each entry:
TAG_Compound("") {
    TAG_String("name"): "minecraft:stone",
    TAG_Compound("states") {
        // block-specific properties
    },
    TAG_Int("version"): ...,
}

// Block at index 0 in the file → network ID 0
// Block at index 1 → network ID 1
// etc.

Dynamic Spawn Position

The spawn Y coordinate is not hardcoded. MC-RS generates the spawn chunk first, then scans the column at (0, 0) to find the highest solid block. The player is spawned 2 blocks above that surface, ensuring they always appear on top of the terrain regardless of which generator is active.

Chunk Streaming

Chunks are sent to players based on their position in the world. The chunk loading flow works as follows:

  1. RequestChunkRadius — The client sends its desired render distance (in chunks).
  2. ChunkRadiusUpdated — The server confirms the actual chunk radius it will provide (may be clamped to a server-configured maximum).
  3. LevelChunk — The server sends chunk data for all chunks within the negotiated radius around the player's position. Each LevelChunk packet contains the serialized sub-chunks, biome sections, and a border block count (0).
  4. NetworkChunkPublisherUpdate — The server announces the center position and radius of the chunk area it considers "published" (loaded and available to the client).

As the player moves, new chunks entering the radius are generated and sent, while chunks leaving the radius are released. Chunks are generated on demand, cached in memory, and persisted to disk.

Persistence: Chunks are stored in LevelDB under worlds/<name>/db. A modified chunk is written back so the world survives restarts; player data (position, inventory, gamemode) is persisted as JSON in players/.

Day/Night Cycle

The world follows a 24,000-tick day cycle, sent to clients via the SetTime packet. Time progresses each server tick when the do_daylight_cycle game rule is enabled.

Tick RangePhaseDescription
0 – 6,000MorningSun rises, sky brightens
6,000 – 12,000MiddayFull daylight
12,000 – 13,000SunsetSun sets, sky dims
13,000 – 23,000NightMoon and stars visible
23,000 – 24,000SunriseNew day begins

Weather

MC-RS supports three weather states: clear, rain, and thunder. Weather transitions are controlled by the do_weather_cycle game rule. When enabled, weather changes occur at random intervals. Weather state can also be set manually via the /weather command.

Implemented

The world system now covers most of vanilla generation and interaction:

  • LevelDB persistence — modified chunks are written to disk and reloaded on restart.
  • Simplex 3D terrain with 11 biomes classified from temperature/rainfall noise.
  • Ores — depth-based vein placement.
  • Trees — species per biome.
  • Structures — villages, temples, mineshafts, strongholds, ocean monuments, Nether/End structures, and more.
  • Multiple dimensions — Overworld, Nether and End.
  • Block updates — server-authoritative break/place with broadcasts; random ticks for crop growth, fire, fluids, etc.
In progress: full vanilla parity for every block behaviour and structure, plus performance tuning of generation and chunk streaming.
